# Ideation Frameworks Reference

## SCAMPER

Transform existing idea with seven operations:

- **Substitute:** Which component, material, or process could you swap out? Replace core technology? Target audience? Business model?
- **Combine:** Merge with another product, service, or idea? Which two things that don't usually go together would create something new?
- **Adapt:** What else is like this? Which ideas from other industries, domains, or time periods could you borrow? What parallel exists in nature?
- **Modify (Magnify/Minimize):** Make it 10x bigger? 10x smaller? Exaggerate one feature? Strip it to absolute minimum?
- **Put to other uses:** Who else could use this? What other problems could it solve? What happens in completely different context?
- **Eliminate:** Remove a feature entirely? Zero-configuration version? Half the steps?
- **Reverse/Rearrange:** Do steps in opposite order? User does work instead of system (or vice versa)? Reverse value chain?

**Best for:** Improving or reimagining existing products/features. Less useful for greenfield ideas.

## How Might We (HMW)

Reframe problems as opportunities with "How Might We..." format:

- Start with observation or pain point
- Reframe it as "How might we [desired outcome] for [specific user] without [key constraint]?"
- Generate multiple HMW framings of same problem. Different framings unlock different solutions.

**Good HMW qualities:**
- Narrow enough to act on ("...help new users find relevant content in their first 5 minutes")
- Broad enough for creative solutions (not "...add a recommendation sidebar")
- Contains tension or constraint that forces creativity

**Bad HMW qualities:**
- Too broad: "How might we make users happy?"
- Too narrow: "How might we add a button to the settings page?"
- Solution-embedded: "How might we build a chatbot for support?"

**Best for:** Reframing stuck thinking. When someone is anchored on solution, pull them back to problem.

## First Principles Thinking

Break idea into fundamental truths, then rebuild from them:

1. **What do we know is true?** (not assumed, not conventional — actually true)
2. **What are we assuming?** List every assumption, even obvious-feeling ones
3. **Which assumptions can we challenge?** For each, ask: "Is this actually a law of physics, or just how it's been done?"
4. **Rebuild from the truths.** With only fundamental truths, what would you build?

**Best for:** Breaking out of incremental thinking. When every idea feels like small improvement on status quo.

## Jobs to Be Done (JTBD)

Focus on what user tries to accomplish, not what they say they want:

- **Functional job:** What task are they trying to complete?
- **Emotional job:** How do they want to feel?
- **Social job:** How do they want to be perceived?

Format: "When I [situation], I want to [motivation], so I can [expected outcome]."

**Key insight:** People don't buy products. They hire them to do a job. Competing product isn't always in same category. (Netflix competes with sleep, not just other streaming services.)

**Best for:** Understanding real problem. When unsure you're solving right thing.

## Constraint-Based Ideation

Impose constraints deliberately to force creative solutions:

- **Time constraint:** "What if you only had 1 day to build this?"
- **Feature constraint:** "What if it could only have one feature?"
- **Tech constraint:** "What if you couldn't use [the obvious technology]?"
- **Cost constraint:** "What if it had to be free forever?"
- **Audience constraint:** "What if your user had never used a computer before?"
- **Scale constraint:** "What if it needed to work for 1 billion users? What about just 10?"

**Best for:** Cutting through complexity. When idea grows too large or too vague.

## Pre-mortem

Imagine idea already failed. Work backwards:

1. It's 12 months from now. Project shipped and flopped. What went wrong?
2. List every plausible failure reason: technical, market, team, timing
3. For each failure mode: Preventable? Signal that idea needs to change?
4. Which failure modes will you accept? Which would kill project?

**Best for:** Phase 2 evaluation. Stress-testing ideas that feel good but haven't been pressure-tested.

## Analogous Inspiration

See how other domains solved similar problems:

- Which industry already solved a version of this problem?
- What would this look like if [specific company/product] built it?
- What natural system works this way?
- What historical precedent exists?

Key: find *structural* similarities, not surface-level ones. "Uber for X" is surface-level. "A two-sided marketplace that solves a trust problem between strangers" is structural.

**Best for:** Phase 1 expansion. Generating variations that feel genuinely different from obvious approach.
