# References, callbacks and Qt ownership

Use [multistream.cpp](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/multistream.cpp) to trace created outputs/services, shared encoders, signal subscriptions, frontend callbacks and dock teardown. For each API call, record whether it returns owned or incremented reference, borrowed object or borrowed string. [Official output API](https://docs.obsproject.com/reference-outputs) distinguishes these: encoder/service getters do not increment references; get_ref and creation do. Match targeted OBS headers when APIs differ. Do not add release to every pointer-returning call or remove a release without tracing independently held creation reference.

Prefer repository's OBS RAII wrappers where available, or small ownership-specific guards for new paths. Balance data/data-array references, encoders, services and outputs on early failure too. Borrowed settings strings must stay backed by their obs_data object until copied. Check null/failure before further creation/start operations. Keep existing main-output requirement when reusing encoders. Keep WHIP bearer-token settings distinct from RTMP stream keys. Preserve documented old config aliases during migration.

OBS output signals can arrive outside Qt widget thread. Queue all widget reads/mutations and shared UI-owned collection changes to one owner, not just setChecked. Existing start/stop callbacks queue some work but also inspect button state and output vector before that handoff. Copying that pattern does not prove thread safety. Follow [Qt thread affinity](https://doc.qt.io/qt-6.8/threads-qobject.html) for selected Qt train.

Context-bound callbacks and QObject parenting help teardown. Raw captured dock/widget pointers still need lifetime reasoning. Preserve [QObject destruction contract](https://doc.qt.io/qt-6.8/qobject.html): parent-owned widgets are not independent unique_ptr owners. Queued invocation targeting destroyed widget can be discarded. So native-reference cleanup must not rely solely on that widget callback running. Release native references through owner/guard with guaranteed cleanup. Guard UI delivery separately with live context/QPointer or equivalent.

Stop is asynchronous. Disconnect OBS signal handlers/frontend callbacks, stop timers and coordinate output stop before destroying callback userdata. Guard old output's queued status from changing a replacement with same display name. Do not erase/release a collection entry concurrently from both stop callback and unload. Hold an appropriate reference while deferred work needs a native object. Callback data is not automatically a retained reference. Preserve shutdown-specific OBS lifetime rules. Do not assume force_stop makes every callback finish synchronously.

Stream-key masking is presentation, not encryption. Keep real keys and endpoints out of logs/fixtures. Keep existing persistence scope unless storage migration is requested. Fork has no observed automated test suite. For lifecycle fix, add focused fake/reference-count and event-order coverage where feasible. Label manual OBS load/start-stop/profile-switch/unload coverage separately. Those checks need no real Twitch broadcast.
