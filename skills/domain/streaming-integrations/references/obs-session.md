# OBS WebSocket v5 sessions

Scala session code is evidence of existing design, not mandate to rewrite Crystal or Rust clients: [SessionLogic.scala](https://github.com/worxbend/obs-websocket-client/blob/fd2f2d05aa4a258b1851d0ed93bb33158977a9ac/core/src/com/worxbend/obs/websocket/client/SessionLogic.scala) and [SessionWire.scala](https://github.com/worxbend/obs-websocket-client/blob/fd2f2d05aa4a258b1851d0ed93bb33158977a9ac/core/src/com/worxbend/obs/websocket/client/SessionWire.scala). Re-check repository's negotiated RPC version before adapting upstream example. Authoritative wire reference: [obs-websocket protocol](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md); match its moving branch to target OBS release.

Keep handshake state machine: Hello (opcode 0), Identify (1), then Identified (2). Requests legal only after identification and successful version negotiation. Password authentication derives challenge response per protocol; never log its inputs or cache challenge-derived value across sessions. Newer offered RPC version is not automatically negotiated.

Request ID names one pending operation within one connection generation. Reserve pending entry before enqueuing send so immediate reply correlates; roll back if enqueueing fails. Check both response opcode (7 for request, 9 for batch) and expected request type. Negative requestStatus means server rejection. On success, absent optional responseData can be empty object if decoder contract permits. Ignore or record late and duplicate replies without completing a different operation.

Timeout, explicit cancellation, disconnect and send failure must all release pending entries and complete callers once. Sender boundary must check canceled requests still queued. Stale timeout callback from old generation must not cancel new request that reused an ID. Dispatch user callbacks outside serialized session actor/lock; callback exceptions must not corrupt correlation state.

Bound outgoing commands and incoming events separately. Overflow behavior follows semantics: dropping old display telemetry may be acceptable; silently dropping commands or transactional replies is not. Surface dropped-event counts. On reconnect, recreate session-scoped subscriptions and refresh state possibly changed during gap. Keep application intent apart from transport queues.

Do not replay command merely because connection was interrupted: Toggle*, scene change and starting/stopping outputs have observable effects, and timeout does not prove non-execution. Authorized retry: inspect or reconcile current state, use bounded retry policy. Test handshake rejection, fast response, wrong type/opcode, duplicate response, timeout/send races, queue saturation, disconnect completion, reconnect with stale timer. Existing Rust [reconnect policy](https://github.com/worxbend/obsctl-rs/blob/d5d732c118a1d5c5a5eb94646f6c8d3f6d0985b4/src/runtime/reconnect_policy.rs) is pure-policy example.
