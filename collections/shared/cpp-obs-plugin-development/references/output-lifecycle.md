# References, callbacks and Qt ownership

Use [multistream.cpp](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/multistream.cpp) to trace created outputs/services, shared encoders, signal subscriptions, frontend callbacks and dock teardown. For every API call record whether it returns an owned reference, an incremented reference, a borrowed object or borrowed string. The [official output API](https://docs.obsproject.com/reference-outputs) distinguishes these: encoder/service getters do not increment references; get_ref and creation do. Match the targeted OBS headers when APIs differ. Do not add release to every pointer-returning call or remove a release without tracing the independently held creation reference.

Prefer the repository's OBS RAII wrappers where available, or small ownership-specific guards for new paths. Balance data/data-array references, encoders, services and outputs on early failure too. Borrowed settings strings must remain backed by their obs_data object until copied. Check null/failure before further creation/start operations; retain the existing main-output requirement when encoders are reused. Keep WHIP bearer-token settings distinct from RTMP stream keys and preserve documented old config aliases during migration.

OBS output signals can arrive outside the Qt widget thread. Queue all widget reads/mutations and shared UI-owned collection changes to one owner, not just setChecked. Existing start/stop callbacks queue some work but also inspect button state and the output vector before that handoff; copying that pattern does not establish thread safety. Follow [Qt thread affinity](https://doc.qt.io/qt-6.8/threads-qobject.html) for the selected Qt train.

Context-bound callbacks and QObject parenting help teardown, but raw captured dock/widget pointers still need lifetime reasoning. Preserve the [QObject destruction contract](https://doc.qt.io/qt-6.8/qobject.html): parent-owned widgets are not independent unique_ptr owners. A queued invocation targeting a destroyed widget can be discarded. Therefore native-reference cleanup must not rely solely on that widget callback executing: release it through an owner/guard with guaranteed cleanup, while separately guarding UI delivery using live context/QPointer or equivalent.

Stop is asynchronous. Disconnect OBS signal handlers/frontend callbacks, stop timers and coordinate output stop before destroying callback userdata. Guard an old output's queued status from changing a replacement with the same display name. Do not erase/release a collection entry concurrently from both stop callback and unload. Hold an appropriate reference while deferred work needs a native object; callback data is not automatically a retained reference. Preserve shutdown-specific OBS lifetime rules rather than assuming force_stop makes every callback finished synchronously.

Stream-key masking is presentation, not encryption. Keep real keys and endpoints out of logs/fixtures; preserve the existing persistence scope unless a storage migration is requested. There is no observed automated test suite in this fork. For a lifecycle fix, add focused fake/reference-count and event-order coverage where feasible, then label manual OBS load/start-stop/profile-switch/unload coverage separately. A real Twitch broadcast is unnecessary for those checks.
