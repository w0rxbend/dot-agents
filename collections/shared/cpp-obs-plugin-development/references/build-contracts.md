# Fork and build compatibility

The reviewed [obs-aitum-multistream CMake root](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/CMakeLists.txt) detects whether CMAKE_PROJECT_NAME is obs-studio. Out-of-tree builds find libobs and obs-frontend-api, linking OBS::obs-frontend-api; in-tree builds link OBS::frontend-api. Both link libobs. Preserve this distinction rather than renaming targets until one local configure passes.

It is a MODULE plugin with Qt6 Core/Widgets, CURL, AUTOMOC/AUTOUIC/AUTORCC and resources.qrc. On the named Unix platforms, Qt below6.9 adds GuiPrivate. That private API is a concrete dependency constraint, not a reason to upgrade Qt or remove the dependency without inspecting consumers. Keep QObject headers/resource files in the build inputs, generated version metadata and plugin output name/install helper consistent. The Windows CRT setting and macOS deployment target are part of artifact compatibility.

[buildspec.json](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/buildspec.json) selects OBS31.0.0-fix1 from a specific fork and hashed OBS/Qt/prebuilt bundles. “Latest OBS docs” does not authorize raising that baseline. Recheck the current checkout before changing dependencies, and validate each supported matrix member rather than claiming Windows/macOS portability from a Linux build.

Use the matching [configure/build presets](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/CMakePresets.json) and [workflow actions](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/.github/workflows/build-project.yaml). Presets inherit OBS dependency-build options; their ENABLE_QT/FRONTEND_API=false values do not mean the plugin stopped using Qt/frontend APIs. Inspect their context before toggling them. The reviewed [format workflow](https://github.com/w0rxbend/obs-aitum-multistream/blob/c48b4bf182f8b354255df7329c9afe3dee4f9820/.github/workflows/check-format.yaml) has jobs disabled with if:false; workflow filenames alone do not establish enforced lint coverage.

For releases inspect actual module/resources/locale placement and linked runtime dependencies. Build, packaging, signing and notarization are separate workflow decisions. A compiled module is not a loaded plugin or a signed installer. Use an isolated OBS profile and local/non-broadcast output for smoke tests; publishing a fork release is a separate requested action.
