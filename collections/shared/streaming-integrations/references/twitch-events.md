# Twitch authorization and event ingress

Use [oauth_setup.py](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/oauth_setup.py), [bot.py](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/bot.py), and [OAuth tests](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/tests/test_oauth_setup.py) for the current local contract. TwitchIO AutoBot delegates significant transport/authentication behavior to the locked library. Confirm whether it uses direct EventSub WebSockets or Conduits; a backend `/ws` endpoint for overlays is a different WebSocket. Direct EventSub WebSocket subscriptions require user tokens; Conduit subscription authorization uses app tokens plus the grants appropriate to each subscription. Consult [Twitch WebSocket authentication/lifecycle](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/) and [Conduit events](https://dev.twitch.tv/docs/eventsub/handling-conduit-events/) for the selected transport.

Match the registered redirect URI byte-for-byte through authorization and code exchange, including scheme, port and `/oauth/callback`. A container bind address such as 0.0.0.0 is not the external redirect URI. Compute permissions from the actual subscriptions and identity relationships: bot ID, broadcaster ID and moderator ID are not interchangeable. Check current subscription-type requirements rather than requesting every scope as a generic repair.

Keep application credentials in configuration and user access/refresh tokens in the existing persistent token store. In twitch-vizer the `.bot_id` sidecar disambiguates a multi-user store; do not guess the first dictionary entry, overwrite other broadcasters during authorization, or replace a token with an empty environment value. Atomically replace token files on the same filesystem. Persist a rotated refresh token before relying on it for future starts.

Distinguish rejected credentials from temporary provider failures. A validation 401 can justify refresh; a provider outage is not evidence that a saved token should be deleted. A rejected refresh may require reauthorization; a transient failure should retain recoverable state. Tests can inject OAuth/client/adapter/browser factories and fake error statuses without contacting Twitch or opening a browser.

For direct EventSub WebSockets distinguish server-directed reconnect from an unexpected drop: the supplied reconnect URL preserves subscriptions, while a new session after a drop needs resubscription and has no automatic replay of missed events. Handle keepalive, revocation, and duplicate notification IDs according to the actual transport/library ownership. Avoid building a second reconnect loop around a library that already owns it.

At the application boundary preserve typed event data and ordering where required. When adding deduplication, carry a stable upstream notification/message ID through ingress, queued events, JSON serialization and frontend normalization. The reviewed [QueuedMessage/VisualEvent schema](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/handler.py) currently omits that ID: its username-derived visual seed is not event identity. Username, text and seed can repeat across legitimate events; define compatibility for older payloads that lack IDs instead of dropping repeated chat by those fields. Bound ingress queues, per-client work, deduplication windows, avatar/emote caches, and send time. Concurrent fan-out prevents serial head-of-line blocking but does not by itself limit a stuck send or memory growth. Test one stalled/disconnected overlay alongside a healthy one. Use synthetic chat/event fragments and separate a transport assertion from a visible scene assertion.
