# Twitch authorization and event ingress

Current local contract: [oauth_setup.py](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/oauth_setup.py), [bot.py](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/bot.py), [OAuth tests](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/tests/test_oauth_setup.py). TwitchIO AutoBot delegates much transport/authentication behavior to locked library. Confirm whether it uses direct EventSub WebSockets or Conduits; backend `/ws` endpoint for overlays is a different WebSocket. Direct EventSub WebSocket subscriptions require user tokens; Conduit subscription authorization uses app tokens plus grants each subscription needs. For selected transport see [Twitch WebSocket authentication/lifecycle](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/) and [Conduit events](https://dev.twitch.tv/docs/eventsub/handling-conduit-events/).

Match registered redirect URI byte-for-byte through authorization and code exchange, including scheme, port and `/oauth/callback`. Container bind address like 0.0.0.0 is not external redirect URI. Derive permissions from actual subscriptions and identity relationships: bot ID, broadcaster ID and moderator ID are not interchangeable. Check current subscription-type requirements; do not request every scope as generic repair.

Keep application credentials in configuration, user access/refresh tokens in existing persistent token store. In twitch-vizer, `.bot_id` sidecar disambiguates multi-user store: do not guess first dictionary entry, overwrite other broadcasters during authorization, or replace token with empty environment value. Replace token files atomically on same filesystem. Persist rotated refresh token before relying on it for future starts.

Separate rejected credentials from temporary provider failures. Validation 401 can justify refresh; provider outage does not justify deleting saved token. Rejected refresh may require reauthorization; transient failure should keep recoverable state. Tests can inject OAuth/client/adapter/browser factories and fake error statuses without contacting Twitch or opening browser.

Direct EventSub WebSockets: server-directed reconnect differs from unexpected drop. Supplied reconnect URL preserves subscriptions; new session after drop needs resubscription and gets no automatic replay of missed events. Handle keepalive, revocation and duplicate notification IDs per actual transport/library ownership. Do not build second reconnect loop around library that already owns it.

At application boundary, keep typed event data and ordering where required. When adding deduplication, carry stable upstream notification/message ID through ingress, queued events, JSON serialization and frontend normalization. Reviewed [QueuedMessage/VisualEvent schema](https://github.com/w0rxbend/twitch-vizer/blob/7fa2861b322a75f9ad5fb395e616645d7f063ab5/backend/vizer/handler.py) currently omits that ID; its username-derived visual seed is not event identity. Username, text and seed can repeat across legitimate events: define compatibility for older payloads lacking IDs instead of dropping repeated chat by those fields. Bound ingress queues, per-client work, deduplication windows, avatar/emote caches and send time. Concurrent fan-out prevents serial head-of-line blocking but alone does not limit stuck send or memory growth. Test one stalled/disconnected overlay beside healthy one. Use synthetic chat/event fragments; keep transport assertions separate from visible scene assertions.
