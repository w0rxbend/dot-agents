# Flix codec and chess compatibility

Evidence is version-specific: [compression Flix pin](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/flix.toml), [porting notes](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/docs/PORTING-NOTES.md), [JVM facade build](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/build.sbt) and [typed bridge seam](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/flix-bridge/src/main/java/org/lichess/compression/flix/FlixCodec.java). When changing versions, recheck their stated Flix version against current checkout and official [Flix docs](https://doc.flix.dev/).

Compression output is persisted storage. Preserve bit order, unsigned-byte handling, fixed integer widths, signed overflow/shift behavior, Huffman/table ordering, padding, truncation, clock defaults. Mathematically cleaner operation may differ from Java/Scala edge semantics. [Clock encoder](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/src/ClockEncoder.flix) takes startTime separately in centiseconds; startTime is not embedded in bytes. Its low-bit truncation deliberately loses precision for some non-final readings. So oracle is specified quantized result, not identity for every encode/decode round trip. Porting notes record differences for pinned Flix version, such as min-value absolute and zero-division behavior. Verify any divergence you rely on with tiny toolchain probe, not general cross-language analogy.

Keep hot immutable precomputed data immutable after construction. Do not propagate region effects merely because temporary arrays built it. Measure table initialization separately from steady-state codec calls. Wrapper that builds tables on every operation can dominate benchmarks without exposing algorithm problem. Match pure/effectful signatures to actual operations, not inferred universal Flix rule.

Generated JVM artifact has unusual namespace seam: existing named-package interface loads its unnamed-package implementation once, then uses typed interface calls. Generated default-package class/package names can shadow familiar JDK names in Java bridge code, so keep fully qualified JDK types and opaque handles at that seam. Do not replace seam with per-call reflection, expose generated implementation classes in stable API, or relocate/shade them without checking all generated references and consumer smoke test.

In observed toolchain, `flix build-jar` output naming follows clone directory behavior. Discover produced artifact; do not assume flix.toml package name. Facade strips test classes for publishing, so inspect release jar separately from working/test jar. Keep Flix, bridge and consumer build steps independent; check supported JDK matrix.

Scalachess-flix is explicitly an experiment, not a drop-in replacement. Read [port review](https://github.com/w0rxbend/scalachess-flix/blob/517af33bf99f353d0c0d40c7bdd6f2eaefc9baba/docs/PORT-REVIEW.md) and [BinaryFen implementation](https://github.com/w0rxbend/scalachess-flix/blob/517af33bf99f353d0c0d40c7bdd6f2eaefc9baba/src/BinaryFen.flix) before claiming feature parity. Binary-position module documents standard-position limits, unsupported variant data, Chess960 castling limitations, stricter malformed-input handling than upstream. Successful standard-FEN round trip proves none of those missing behaviors. Flix type aliases also lack original opaque-newtype guarantees. Decide whether public boundary needs checked constructors/wrappers; do not assume they are zero-cost.

Perft independently checks move generator per position/variant/depth. Perft does not validate PGN/SAN parsing, binary serialization, clocks, ratings or all game termination rules. Keep upstream corpus provenance and exact depth/node expectations. Do not treat resemblant fixture names or percentage of ported source lines as evidence that fixture contents and assertions match upstream.
