# Flix codec and chess compatibility

Evidence is version-specific: [compression Flix pin](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/flix.toml), [porting notes](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/docs/PORTING-NOTES.md), [JVM facade build](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/build.sbt) and [typed bridge seam](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/flix-bridge/src/main/java/org/lichess/compression/flix/FlixCodec.java). Recheck their stated Flix version against the current checkout and official [Flix docs](https://doc.flix.dev/) when changing versions.

Compression output is persisted storage. Preserve bit order, unsigned-byte handling, fixed integer widths, signed overflow/shift behavior, Huffman/table ordering, padding, truncation and clock defaults. A mathematically cleaner operation may differ from Java/Scala edge semantics. The [clock encoder](https://github.com/w0rxbend/compression-flix/blob/920b0514bb1c34fe3bb5f25c4dbaad78e0c2a1ee/src/ClockEncoder.flix) takes startTime separately in centiseconds; it is not embedded in the bytes. Its low-bit truncation deliberately loses precision for some non-final readings, so the oracle is the specified quantized result, not identity for every encode/decode round trip. The porting notes record differences such as min-value absolute behavior and zero-division behavior for the pinned Flix version; verify any used divergence with a tiny toolchain probe instead of relying on a general cross-language analogy.

Keep hot immutable precomputed data immutable after construction; do not propagate region effects merely because temporary arrays were used to build it. Measure table initialization separately from steady-state codec calls. A wrapper that constructs tables on every operation can dominate benchmarks without exposing an algorithm problem. Match pure/effectful signatures to the actual operations, not an inferred universal Flix rule.

The generated JVM artifact has an unusual namespace seam. The existing named-package interface loads its unnamed-package implementation once, then uses typed interface calls. Generated default-package class/package names can shadow familiar JDK names in Java bridge code; retain fully qualified JDK types and opaque handles at that seam. Do not replace it with per-call reflection, expose generated implementation classes in a stable API, or relocate/shade them without checking all generated references and a consumer smoke test.

`flix build-jar` output naming follows clone directory behavior in the observed toolchain. Discover the produced artifact rather than assuming the flix.toml package name. The facade strips test classes for publishing; inspect the release jar separately from the working/test jar. Preserve independent Flix, bridge and consumer build steps and check the supported JDK matrix.

Scalachess-flix is explicitly an experiment, not a drop-in replacement. Read [port review](https://github.com/w0rxbend/scalachess-flix/blob/517af33bf99f353d0c0d40c7bdd6f2eaefc9baba/docs/PORT-REVIEW.md) and [BinaryFen implementation](https://github.com/w0rxbend/scalachess-flix/blob/517af33bf99f353d0c0d40c7bdd6f2eaefc9baba/src/BinaryFen.flix) before claiming feature parity. The binary-position module documents standard-position limits, unsupported variant data, Chess960 castling limitations and stricter malformed-input handling than upstream. A successful standard-FEN round trip proves none of those missing behaviors. Flix type aliases also lack the original opaque-newtype guarantees; decide whether checked constructors/wrappers are needed at a public boundary without assuming they are zero-cost.

Perft is an independent move-generator check, per position/variant/depth. It does not validate PGN/SAN parsing, binary serialization, clocks, ratings or all game termination rules. Preserve upstream corpus provenance and exact depth/node expectations. Do not treat resemblant fixture names or the percentage of ported source lines as evidence that fixture contents and assertions match upstream.
