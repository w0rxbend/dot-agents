# Cargo scope and learning contracts

## Preserve the observed workspace

The pinned [rust-playground workspace](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/Cargo.toml) is virtual, explicitly uses resolver 2, and includes exercises, katastrophes, zephyr and tippletracker packages. [exercises](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/exercises/Cargo.toml) and the tippletracker manifests use edition 2024; [katastrophes](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/Cargo.toml) and zephyr use 2021. Most dependency tables are empty; zephyr-cli has a path dependency on zephyr-common. Inspect current contents instead of inventing implemented authentication/database services from package names.

A member's edition does not choose a virtual workspace's resolver. Changing resolver 2 to 3 changes dependency selection policy and belongs to an intentional migration, with toolchain/lockfile compatibility checked independently. Sharing a workspace lockfile also does not imply every package inherits the same edition. [Cargo workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html), [dependency resolver](https://doc.rust-lang.org/cargo/reference/resolver.html).

For a kata edit, plausible existing checks are `cargo check -p katastrophes --locked` and `cargo test -p katastrophes --locked`. For a zephyr-common API change, include its zephyr-cli consumer. Select actual package names rather than directory basenames, and inspect test counts: filtering for a nonexistent test may succeed without testing the changed behavior. In a virtual workspace, an unqualified root command can select all members; use that broader scope when a cross-workspace change justifies it. [Cargo test selection](https://doc.rust-lang.org/cargo/commands/cargo-test.html).

`cargo check` does not execute tests or produce evidence of runtime behavior. Existing Rustfmt/Clippy policy can add cheap feedback; preserve the supported feature/target combinations and do not impose `-D warnings` on a tutorial merely because production CI elsewhere uses it. Building tests with `--no-run` and actually executing them are distinct results. [Cargo check](https://doc.rust-lang.org/cargo/commands/cargo-check.html), [Clippy usage](https://doc.rust-lang.org/clippy/usage.html).

## Source-specific exercise decisions

The inspected [exercises main](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/exercises/src/main.rs) demonstrates parsing, platform-sized integers, input and safe array lookup. It intentionally reads stdin, parses an index with `expect`, and falls back to zero for a missing element. A compile/test command is different from an interactive `cargo run`; do not start the latter and wait indefinitely without a reason to exercise input. When improving user input handling, preserve the agreed missing-element behavior and distinguish EOF, I/O failure, invalid number and out-of-range index.

[high_and_low](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/high_and_low.rs) currently parses with `unwrap`, sorts, and has two happy-path tests. A kata can legitimately assume valid nonempty input. If the task makes it reusable or changes accepted inputs, decide the empty/malformed-input contract and test it; a `Result` conversion changes the function interface and callers. [Recoverable errors](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html).

[maskify](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/maskify.rs) measures and slices byte offsets while its comment describes characters. For non-ASCII support, define whether the last four units are bytes, Unicode scalar values or grapheme clusters. `str::len` is bytes; a byte slice boundary can fall inside a UTF-8 character. Use valid boundaries or character iteration when that is the intended contract. Test lengths around four and multibyte input; `chars()` does not perform grapheme segmentation. Keep an ASCII-only kata simple when its actual contract is ASCII. [Rust str documentation](https://doc.rust-lang.org/std/primitive.str.html).

[get_sum](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/get_sum.rs) sums an inclusive integer range. Replacing iteration with a formula changes overflow and range-size behavior: choose checked or wider arithmetic and preserve reversed/equal-endpoint behavior. Do not infer correctness from faster happy-path execution, or rely on differing debug/release overflow behavior. [Checked integer arithmetic](https://doc.rust-lang.org/std/primitive.i64.html#method.checked_add).

These are original review observations, not copied kata implementations. Retain existing attribution and educational constraints when modifying the source.
