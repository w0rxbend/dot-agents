# Cargo scope and learning contracts

## Preserve the observed workspace

Pinned [rust-playground workspace](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/Cargo.toml) is virtual, explicitly uses resolver 2, and includes exercises, katastrophes, zephyr and tippletracker packages. [exercises](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/exercises/Cargo.toml) and tippletracker manifests use edition 2024; [katastrophes](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/Cargo.toml) and zephyr use 2021. Most dependency tables are empty; zephyr-cli has path dependency on zephyr-common. Read current contents instead of inventing implemented authentication/database services from package names.

Member edition does not pick a virtual workspace's resolver. Changing resolver 2 to 3 changes dependency selection policy: do it only in an intentional migration, checking toolchain/lockfile compatibility separately. Shared workspace lockfile does not imply shared edition. [Cargo workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html), [dependency resolver](https://doc.rust-lang.org/cargo/reference/resolver.html).

For a kata edit, plausible existing checks: `cargo check -p katastrophes --locked` and `cargo test -p katastrophes --locked`. For a zephyr-common API change, include its zephyr-cli consumer. Use actual package names, not directory basenames. Check test counts: filtering for a nonexistent test may pass without testing changed behavior. In a virtual workspace, unqualified root command can select all members; use that wider scope when a cross-workspace change justifies it. [Cargo test selection](https://doc.rust-lang.org/cargo/commands/cargo-test.html).

`cargo check` does not run tests or prove runtime behavior. Existing Rustfmt/Clippy policy can add cheap feedback. Keep supported feature/target combinations. Do not impose `-D warnings` on a tutorial merely because production CI elsewhere uses it. Building tests with `--no-run` differs from executing them. [Cargo check](https://doc.rust-lang.org/cargo/commands/cargo-check.html), [Clippy usage](https://doc.rust-lang.org/clippy/usage.html).

## Source-specific exercise decisions

Inspected [exercises main](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/exercises/src/main.rs) demonstrates parsing, platform-sized integers, input and safe array lookup. It intentionally reads stdin, parses an index with `expect`, and falls back to zero for missing element. Compile/test commands differ from interactive `cargo run`; do not start `cargo run` and wait indefinitely without reason to exercise input. When improving user input handling, keep agreed missing-element behavior and distinguish EOF, I/O failure, invalid number and out-of-range index.

[high_and_low](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/high_and_low.rs) currently parses with `unwrap`, sorts, and has two happy-path tests. Kata may assume valid nonempty input. If task makes it reusable or changes accepted inputs, decide and test empty/malformed-input contract. `Result` conversion changes function interface and callers. [Recoverable errors](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html).

[maskify](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/maskify.rs) measures and slices byte offsets, but its comment says characters. For non-ASCII support, define whether last four units are bytes, Unicode scalar values or grapheme clusters. `str::len` counts bytes; byte slice boundary can fall inside a UTF-8 character. Use valid boundaries or character iteration when that is the intended contract. Test lengths around four and multibyte input; `chars()` does not do grapheme segmentation. Keep ASCII-only kata simple when its contract is ASCII. [Rust str documentation](https://doc.rust-lang.org/std/primitive.str.html).

[get_sum](https://github.com/w0rxbend/rust-playground/blob/167792d514e0a72ca7b53c4cfbb5207c6973d523/katastrophes/src/get_sum.rs) sums an inclusive integer range. Replacing iteration with a formula changes overflow and range-size behavior: use checked or wider arithmetic, keep reversed/equal-endpoint behavior. Do not infer correctness from faster happy-path runs or rely on differing debug/release overflow behavior. [Checked integer arithmetic](https://doc.rust-lang.org/std/primitive.i64.html#method.checked_add).

These are original review observations, not copied kata implementations. When modifying source, keep existing attribution and educational constraints.
