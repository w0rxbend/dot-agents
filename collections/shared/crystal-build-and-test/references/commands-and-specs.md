# Select commands by evidence

Use the installed compiler's help and the [official compiler manual](https://crystal-lang.org/reference/1.19/man/crystal/index.html), switching documentation version when the checkout/toolchain differs. A normal focused workflow is `crystal tool format --check src spec`, `crystal spec spec/path_spec.cr`, then the full `crystal spec` when behavior dependencies warrant it. Confirm flags on historical compilers. `crystal build src/main.cr -o <scratch-output>` builds an executable; `crystal run` compiles and executes it. Specs also compile and execute. Compiler/macro-time subprocesses can still run during a build, so inspect source/manifest hooks when choosing isolated checks.

Read the [Shards manual](https://crystal-lang.org/reference/1.19/man/shards/index.html) for the selected version. `shards install` resolves/downloads into `lib` and creates or uses `shard.lock`; `shards update` intentionally refreshes resolution. Do not replace install with update as a generic repair. Keep application dependency locks reviewable; follow the repository's existing policy for libraries. Build declared executable targets with `shards build <target>` when supported; the playground's target is `starter`, not its repository name. Its manifest presently has no dependencies, so dependency fetching is not automatically needed for every source edit.

The [official testing guide](https://crystal-lang.org/reference/1.19/guides/testing.html) describes `Spec` and `*_spec.cr`. Add behavior assertions at the real requireable boundary: exact streamed bytes, empty/non-ASCII input where supported, failures and relevant ownership cleanup. Never replace a failed expected value with implementation output solely to pass. If a subprocess or socket participates, use an existing fake/temporary resource seam before a live service check. A spec dry-run is not execution evidence.

Run benchmarks only for a performance request and with equivalent inputs/output contracts, compiler optimization, architecture and buffer-reset conditions recorded. Report throughput/allocation results separately from formatting/build/spec status. Avoid generalizing one IO microbenchmark to all serializers or all supported compilers.
